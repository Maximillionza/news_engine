ACE Tuning Map

Every input in ASE_Config.mqh (153 of them), grouped by what part of the machine it touches, in plain language: what turning it up or down actually changes downstream. Defaults shown are the file's current values, not recommendations.

How to read this — most knobs here feed the legacy score cascade (the system that actually places trades today). A separate block near the bottom belongs to the v4 evidence/adaptive layer, which currently only observes — changing those numbers won't move a live trade until that layer is given execution authority.

01 Risk & position sizing

Controls how big a trade is and what reward ACE insists on before it'll take one.

InputDefaultWhat moving it does
InpRiskPercent0.50% of account risked per trade. Double it and every position size doubles — same win rate, double the swings in both directions.
InpMinRR2.0Minimum reward-to-risk ACE will accept. Raise it and fewer setups qualify (TP has to be further from entry than SL), but the ones that do pay more per win. Lower it and more setups pass, with smaller average wins.

02 Stops & targets (ATR-based)

ATR (Average True Range) is the ruler ACE uses for "how far is a normal move right now." Every SL/TP is a multiple of it.

InputDefaultWhat moving it does
InpATRPeriod14How many M15 bars the ruler is averaged over. Smaller = ruler reacts faster to a sudden vol change but gets noisier; larger = smoother but slower to adapt.
InpATRMultiplierSL1.0Baseline SL distance (used in Compression). Raise it → wider stop, fewer stop-outs on noise, bigger loss when wrong.
InpATRMultiplierSL_Wide1.5Same idea for Ranging regime specifically — kept separate because ranging price chops more.
InpATRSLCap15.0Hard ceiling on SL in points regardless of ATR — a sanity backstop so a volatility spike can't blow the stop out to something unreasonable. 0 removes the ceiling.
InpATRMultiplierTP1 / TP22.0 / 4.0First/second target distance, ATR mode only. TP1 is usually where partial profit is taken; TP2 is the "let it run" target.
InpATRTrailMultiplier1.5How far behind price the trailing stop sits once trailing is active. Tighter = locks in profit sooner but gets shaken out of trends more; wider = rides trends further but gives back more on a reversal.
InpTP1Mode / InpTP2ModeTP_ATRGlobal fallback: fixed ATR multiple (consistent everywhere) vs structural (aims at an actual swing level, more precise but not always available) vs hybrid (structural, clamped inside ATR bounds). Per-regime overrides below take priority when set.

03 Directional bias & structure (H4 → H1 → M15 → M1)

This is the top-down chain that decides which direction ACE is even allowed to look for a trade in, before any entry logic runs.

InputDefaultWhat moving it does
InpH4FastEMA / SlowEMA20 / 50H4 bias vote: fast above slow = long bias, below = short. Shrinking the gap between the two periods makes the H4 vote flip direction more often (more reactive, more whipsaw); widening it makes the vote sticky.
InpH1SwingPivot2Bars either side needed to confirm an H1 swing high/low. Raise to 3+ for fewer, more "real" pivots; direction changes become rarer and later.
InpH1SwingLookback10How far back (H1 bars) it scans for swing points. Wider window = catches older structure, narrower = only reacts to recent price.
InpPivotBackfillBars200One-time historical scan depth at EA startup to seed the pivot registry. Mostly a startup-only setting.
InpPivotMaxAgeBars120An unbroken H1 pivot expires after this many bars (~5 trading days) and stops counting as a valid BOS target. Shorten it and old levels get discarded faster; lengthen it and stale levels linger longer.
InpBiasInvalidATRMult2.0If price runs this many H4-ATRs against the held bias, the bias resets to neutral rather than staying locked on an old view. Lower it = bias gives up sooner on adverse moves; 0 disables this safety check entirely.
InpH1BiasStaleBars120If no fresh H1 BOS fires within this many bars, bias goes stale and resets to neutral — stops a Monday bias from still driving Thursday's trade. 0 disables it.
InpM15EMA21The M15 dynamic support/resistance line several setup checks reference.
InpM1FastEMA / SlowEMA9 / 21Feeds the weakest of the four M1 trigger types (EMA-aligned fallback). Narrower gap = fires more often but with less conviction behind each signal.

04 Execution basics & instance identity

InputDefaultWhat moving it does
InpMaxSpread70ptHard gate — no trade at all if live spread exceeds this, regardless of everything else.
InpSpreadBaseline35The "as good as it gets" spread for the score curve — spreads near this score close to full marks, not just "under the cap."
InpMaxPositions1Concurrent open positions allowed. Raising it lets ACE stack trades — increases exposure and correlation risk fast on a single-symbol EA.
InpCooldownBars5 (M15)Forced pause after a close before ACE will look again (~75 min at default). Shorter = re-enters faster after a stop-out; longer = avoids revenge-trading the same failed level.
InpMagicNumber203157 / 204001 (v4.0.1)Instance identity — must differ between two builds run side by side, or each one's trade-management code will act on the other's live positions.

05 Sessions & kill zones — your London example lives here

Controls when ACE is even allowed to be looking for trades, and how it scores "time of day" as part of the entry score.

InputDefaultWhat moving it does
InpUseLondon / InpUseNYtrue / trueMaster on/off switches per session. Turn one off and ACE won't look for entries during that window at all.
InpTrade24_7falseOverrides everything above — ignores session filtering entirely if true.
InpKillZoneEnabledtrueGives the ICT kill-zone windows a session-quality bonus (10.0 vs 9.5 for plain overlap). Off = all session time scored the same, no kill-zone premium.
InpLondonStartHour/Min06:00 UTCYour example — set this from 7 to 6 and ACE starts treating 06:00–07:00 UTC as inside the London session an hour earlier: it becomes eligible for session score, kill-zone scoring (if that hour falls in the fixed 08:00–11:00 KZ window it won't change, since KZ times are separate constants — see below), and the whole WAIT_SETUP/WAIT_TRIGGER pipeline gets an extra hour of "session is open" runway. It does not move the ICT kill zone itself.
InpLondonEndHour/Min12:30 UTCSame logic at the other end — later close = more session-open hours per day.
InpNYStartHour/Min, InpNYEndHour/Min12:30–21:00 UTCSame mechanics as London, for the NY window.
The 08:00–11:00 London / 13:00–16:00 NY kill-zone windows are separate fixed constants inside the code comments (not their own input here) — moving InpLondonStartHour widens or shrinks the session, it does not relocate the kill zone itself. If you want the kill zone to shift, that's a different, currently-hardcoded value.

06 Composite scoring gate

InputDefaultWhat moving it does
InpScoreThreshold60.0Global minimum composite score (0–100) to enter — per-regime profiles below override this per market condition.
InpMinBiasScore0 (off)If set, the H4-bias component alone must clear this raw floor, no matter how high other components score — stops a weak bias being "rescued" by a strong M15 setup.
InpMinSetupScore0 (off)Same idea for the M15 setup-class component.

07 Setup-class & trigger-class switches

On/off toggles per pattern type, mostly added after backtests showed a specific combination losing money in a specific regime.

InputDefaultWhat moving it does
InpBiasReEvalBars8How long a bias-block from a 4/4 M15 conflict holds before it auto-clears. Lower = ACE gets unstuck faster after disagreement; higher = more conservative, waits longer before trying again.
InpBiasFlipCycles3How many full re-block cycles of persistent conflict before ACE forces a fresh H4 read and accepts even a flipped direction.
InpFVGMaxBars10 (~2.5h)Rejects a fair-value-gap setup once it's older than this — edge decays with age. 0 = no age limit.
InpEnableFVG / Displacement / CompressionBO / EMAPullbacktruePer-setup-class kill switches. Turn one off after your own attribution data shows it's a net loser in a specific regime.
InpEMAFallbackInRangingfalseBlocked by default — backtest showed this the worst-performing trigger in Ranging (avg −$21/trade). Setting true restores it.
InpEMAFallbackInTrendingfalseSame trigger, blocked in Trending too — it drove almost all of Trending's net loss in a 335-trade backtest.
InpWeakShortTriggersInTrendingfalseBlocks Rejection/Displacement triggers specifically on SHORT in Trending (Disp+mBOS stays exempt) — Trending+Short was the weakest cell found in backtest (37% WR vs 52% for Long).
InpRegimeFilterEnabledtrueMaster switch for regime-based gating entirely. Off = one set of rules for every market condition.
InpLiquidityConfirmtrueRequires a liquidity-sweep confirmation on top of the M1 trigger. Off = trades on trigger + score alone, faster but less confirmed.
InpPartialTPEnabled / InpPartialTPPercenttrue / 50%Whether/how much position closes at TP1. Higher % locks in more profit early, leaves less size to run to TP2.
InpATRTrailEnabledtrueWhether the ATR-based trailing stop is active at all once a position is open.

08 Daily reset & staleness guards

InputDefaultWhat moving it does
InpDailyResetHour0 (midnight UTC)When the pipeline clears gate state and starts a fresh evaluation each day (only if flat). Structural memory (H1 pivots/BOS) survives the reset if still fresh.
InpOffSessionBiasGuardtrueBlocks off-session entries until the new UTC day's first H1 bar has processed — stops yesterday's bias carrying into pre-London hours with stale context. Added after two overnight losses traced to exactly this.

10 Drawdown survival

InputDefaultWhat moving it does
InpDDHaltPct30%Drawdown % that halts trading entirely. Risk is already tiered down in thirds on the way there (1.00× → 0.75× → 0.50× → halt). Raise it and ACE tolerates a deeper hole before stopping; lower it and it stops earlier but more often on normal variance. 0 disables the halt — not recommended live.
InpDDRecoveryModetrueIf true, a halt starts a "recovery phase" measured from the reduced balance instead of stopping until manual reload — see the long lifecycle comment in the file for the exact phase logic. False = old behaviour, one halt and it's over until you restart the EA.
InpSpreadSpikeMultiplier1.5×How far spread has to jump above its entry-time value before trade management treats it as a spike event.

11 Order execution resilience

InputDefaultWhat moving it does
InpExecRetries3Order-send retry attempts before giving up on a fill.
InpExecSpreadShockMult2.5×Aborts execution outright if spread at the moment of sending is this many times the average — protects against fat-finger fills during a liquidity gap.
InpSlippageGateATRMult0.8If price has drifted this many M1-ATRs from the trigger bar's close by the time the order actually fires, the entry is aborted. Lower = stricter about fill quality, more valid setups get vetoed on ordinary drift; 0 disables the gate.
InpSlippageAdverseOnlytrueOnly counts drift that made the fill worse against the gate above — a better-than-expected fill no longer aborts a good trade (this was a real bug fixed in v3.14.5).

12 Per-regime profiles (Trending / Ranging / Compression / Manipulation)

Each market regime gets its own SL width, score bar, spread cap, and TP mode — because a Trending-day setting applied to a choppy Ranging day (or vice versa) is where most of ACE's historical losses trace back to. High-Vol has no profile; it's a hard block.

RegimeSL ×ATRScore barNotable override
Trending1.8, cap 15pt60.0TP modes set to Structural (aims at real swing levels — trend has momentum to reach them). Counter-trend gates (InpCTEMASepThreshold etc.) add extra scrutiny to trades against a strongly-separated H4 EMA.
Ranging2.4, cap 20pt55.0Widest SL of the four (oscillation needs room) but the lowest score bar — deliberately easier to qualify since ranging setups are more common and lower-conviction by nature.
Compression1.8, cap 8pt75.0InpCompressionMode=0 — new entries are blocked entirely by default, breakout-watch only. A 335-trade backtest showed compression trading at 16% win rate / −$532 net; this mode was flipped off after that data came in.
Manipulation1.6, cap 14pt75.0Tightest SL, same high score bar as Compression (sweep/reversal setups need to be genuinely strong to qualify). TP1 targets the swept level structurally rather than a fixed ATR multiple.
Each regime also has its own InpSpread_* and InpBiasConf_* — same mechanics as the global versions above, just scoped to that regime.

13 V4 authority & adaptive learning observation-only by default

This block governs whether the confluence/archetype system is allowed to trade at all, and how cautiously it's allowed to earn that trust.

InputDefaultWhat moving it does
InpAceV4ModeACEV4_EVIDENCELegacy = v4 pipeline doesn't run at all. Evidence = today's setting, watches/logs/learns, zero execution power. Advisory = visible but still no authority. Conditional/Active = can actually place trades once validated. This is the single most consequential switch in the whole file for "will the new system ever fire a trade."
InpAceV4AuthCautiousMin / ControlledMin / ValidatedMin20 / 50 / 100Observation counts (per archetype bucket) required before each trust tier unlocks. Lower these and the system earns authority faster on thinner evidence; raise them for a more conservative rollout.
InpAceV4MinSeparation15Minimum long-vs-short score gap required before a direction is even considered — too close a contest and it stays flat.
InpAceV4ResearchOnlyfalseHard override — set true and V4 can never get execution authority no matter what mode or validation says. The safety switch of last resort.
InpAceV4AdaptLearningRate0.20How aggressively the adaptive layer nudges its own thresholds per observation batch. Higher = adapts faster but risks chasing noise; lower = more stable, slower to react to genuine regime shifts.
InpAceV4OOSMinSamples / MinOOSRetention20 / 0.85Out-of-sample validation bar a candidate archetype/threshold must clear before being trusted — retention is how much of the in-sample edge has to survive on unseen data.
InpAceV4FreshnessMax(M1/M15/H1)Bars5 / 8 / 12How stale a piece of evidence is allowed to be before it's discarded from the confluence read — trigger-level evidence goes stale fastest (5 M1 bars), structure-level slowest (12 H1 bars).
