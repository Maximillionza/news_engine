**New-event onboarding rule (2026-09-13) — check the causation matrix before adding config for a new event:** when a candidate event (e.g. a newly relevant calendar release) comes up for possible tracking, check `docs/News_Engine_Causation_Matrix_v2.xlsx` — specifically `Layer1_Event_to_USD`, `Layer2_Asset_Transmission`, and the per-event `POC_*` sheets — for how that event is already classified, BEFORE reaching for the usual config additions (`EVENT_SURPRISE_DIRECTION`, `ACCUMULATOR_MEDIUM_ALLOWLIST`, `EVENT_RELEVANCE_KEYWORDS_BY_TITLE`, `PRINT_SURPRISE_LEXICON`, a Kalshi ticker). Two real outcomes, not one default:
- **Standalone, with its own documented USD/instrument transmission channel** (e.g. Unemployment Claims, CPI, PPI) — worth the full config treatment and its own Dashboard card.
- **Input-only — named in the workbook as one of several signals feeding a DIFFERENT event's Tier 1 methodology**, with no standalone transmission channel of its own documented (e.g. Philly Fed Manufacturing Index — one of five regional Fed districts averaged into the leading indicator for both PPI and ISM Manufacturing PMI, and explicitly flagged in `POC_PPI_Leading_Indicators` as noisy taken alone: *"Philly Fed's own prices-paid swung from 53.9 to 40.9 in one month"*). An input-only event needs **no standalone config and no Dashboard card** — the Tier 1 research for whichever event it feeds already reads it live (WebSearch, at research time) as part of that blended signal. Giving it its own essence score would put a confident-looking BUY/SELL call in front of the user for a number this project's own sourced research says isn't reliable read alone — a real mistake, not a harmless extra.

Real case this rule exists because of: Philly Fed Manufacturing Index was initially scoped for the full 4-entry config treatment (2026-09-13) before checking `POC_PPI_Leading_Indicators` surfaced that it's explicitly input-only and explicitly flagged as unreliable standalone — the scope was dropped, correctly, once checked.

## 1. The engine as designed — three layers, one holistic view

The workbook's own README (written before any of Option A existed) describes an architecture the codebase never fully built. Restated in the terms clarified this session:

1. **News/sentiment engine** (the original, pre-Causation-Matrix core) — lexicon + FinBERT/Claude sentiment over RSS/news articles. Opinion-based, live, continuously re-scoring. **This is the only layer that's fully shipped.**
2. **Tier 1 — per-event numeric calculation** ("pure maths, not opinion") — a real-data-driven, sourced read of what a specific print is likely to show, one methodology per event type, always judged by hand rather than computed (deliberate, not a gap — see below). **Shipped for all 9 tracked event types** (2026-09-11, Batch 7) — CPI and PPI have live `Tier1Prediction` rows from real occurrences; the other 7 (NFP, FOMC/Meeting Minutes/Federal Funds Rate, the 3 GDP variants, Core PCE, ISM Manufacturing, Retail Sales/Core Retail Sales) have their methodology wired into the scheduled task's prompt and will log automatically the first time a real occurrence enters the 3-day lookahead. ISM Services PMI is the one honest exception: no verified leading indicator exists in the sourced research, so it's deliberately wired to log `confidence="Guessing"` rather than force a call — a real research gap, not an unbuilt one. (Update 2026-09-13: this line was previously stale, written before Batch 7 shipped the same day — corrected here.)
3. **Tier 2/3 — exogenous market context** (oil price shocks, geopolitical/war events, Fed-independence shocks, Treasury buyback changes, tariff actions, government shutdowns) — deliberately *not* part of any single event's calculation, because these can happen independently of and on top of any scheduled release. **Detection, persistence, scheduled trigger, and live confidence-downgrade display are shipped (Batch 6, 2026-09-11).** `AdHoc_Category_Taxonomy` and `Discovery_Detector_Spec` are now real code (`data_layer/discovery_detector.py`, `scoring/backtest_store.py`'s `exogenous_shocks` table, `webapp/predictions_service.py`'s `tier1_confidence_downgrade`). `Periodic_Qualitative_Calendar` and the causal-chain knowledge base (`Layer1_Event_to_USD` → `Layer2_Asset_Transmission`, meant to connect a classified shock to a specific instrument's transmission mechanism, not just downgrade confidence generically) remain documented-only, explicitly out of scope for this batch. See §2c.

The 2026-09-10 PPI miss (Tier 1 called `Certain`/bullish, wrong) was a direct symptom of shipping layer 2 in isolation with layer 3 never built — nothing in the live system checked "was anything exogenous happening that day" before treating Tier 1's narrow calculation as a standalone verdict. Batch 6 closes that specific gap for the confidence dimension (an unresolved exogenous shock now downgrades every tracked instrument's Tier 1 confidence, never its direction); it does not close it for the causal-chain/transmission-nuance dimension, which stays future work.
