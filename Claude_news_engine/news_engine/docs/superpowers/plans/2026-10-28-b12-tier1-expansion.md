# B12 — Implementation Plan

**Goal:** Widen Tier 1 from 2 formula titles to 5 formula + 6 market-implied titles, all captured deterministically by the existing Windows Tier 1 tasks: Core PCE m/m, CPI y/y and Core CPI y/y from the Cleveland Fed nowcast files (T9, T11); NFP, Retail Sales, PPI, Federal Funds Rate, ISM Manufacturing PMI and Advance GDP from Kalshi's public ladders through a fixed implied-median rule (T10); and label CME FedWatch-sourced rows "market-implied" everywhere Tier 1 is shown (FedWatch fix).

**Architecture:** `data_layer/tier1_events.py` stays the single registry: the tier of a title names its only producer (formula = Cleveland capture, market_implied = Kalshi capture, judgment = LLM research task), and `tier1_row_tier(source, value)` labels stored rows (formula source, Kalshi source and FedWatch citations route to their tiers). The Cleveland capture learns a second file (`nowcast_year.json`) through a title -> (file, series) map; a new pure module `webapp/tier1_market.py` turns a Kalshi strike ladder (new `kalshi_feed.get_ladder`) into an implied median and a side vs forecast, and a new orchestrator `scripts/capture_tier1.py` runs both phases from the unchanged task path (`tier1_capture_scheduled.bat` -> 07:00 SAST daily 48h + Monday 192h, catch-up on wake).

**Spec reference:** `docs/roadmap-2026-10-20.md` §B12 (T9, T10, T11; T12 already live via B9a) plus the owner decisions in the B12 brief: verify Cleveland and Kalshi series live before mapping; a Tier 1 row exists only when its source produced a value before the release (no row on missing data, never a row after release, B3 rule T6); 70/30 Combined, B9 ST1/ST2 and B9a agreement/tier semantics unchanged; one Tier 1 producer per release; dry-run mode for the capture; FedWatch rows route to market_implied through the shared helper.

## Global Constraints

- A Tier 1 row is written only from a value the source actually produced before the release; missing value, missing forecast, illiquid or uncrossed ladder, unknown event = no row, reported. Nothing is written when `now >= release` (both writers raise `ValueError`), and due releases are strictly after `now`.
- One producer per title: formula titles are written only by the Cleveland phase, market_implied only by the Kalshi phase, judgment only by `scripts/tier1_research.py` (which refuses the other two tiers). The call of record is the latest pre-release row (existing readers, unchanged).
- `combine`, `TIER1_WEIGHT`/`NEWS_WEIGHT` (70/30), `news_side`, agreement and `compute_tier1_sentiment_conflict` are not edited; no "conflicting" status; `tier1_tier` only gains real `market_implied` values.

- Kalshi access is read-only public GETs under `KALSHI_BASE_URL` (`/events`, `/markets`) only; no auth, no trading endpoint.
- Do not touch `alerting/*`, the shock-alerts route/JS, `scripts/compute_release_reactions.py`, `data_layer/minute_bars.py` (B10), the Market reaction tab, or any ACE/EA/MT5 material.

  - `@dataclass(frozen=True) class MarketSeries: series_ticker: str; ticketing: str; strike_divisor: float; discrete: bool; surprise_direction: str`.
  - `MARKET_SERIES: dict[str, MarketSeries]`: `"Non-Farm Employment Change": ("KXPAYROLLS", "reference_month", 1000.0, False, "higher_bullish")`, `"Retail Sales m/m": ("KXUSRETAIL", "release_date", 1.0, False, "higher_bullish")`, `"PPI m/m": ("KXUSPPI", "release_date", 1.0, False, "higher_bullish")`, `"ISM Manufacturing PMI": ("KXISMPMI", "reference_month", 1.0, False, "higher_bullish")`, `"Advance GDP q/q": ("KXGDP", "release_date", 1.0, False, "higher_bullish")`, `"Federal Funds Rate": ("KXFED", "meeting_month", 1.0, True, "higher_bullish")`. Comment: Fed Funds and Advance GDP have no `EVENT_SURPRISE_DIRECTION` entry; higher = USD-bullish is the accumulator's own Fed convention and Prelim GDP's mapped sign.
  - `MIN_OPEN_INTEREST = MIN_KALSHI_OPEN_INTEREST` (10.0), `MAX_SPREAD = 0.25`, `NO_FORECAST = "no readable forecast yet"`.
  - `@dataclass(frozen=True) class MarketCall: event_ticker: str; implied_value: float; side: int; liquid_strikes: int`.
  - `survival_points(ladder: KalshiLadder, divisor: float) -> list[tuple[float, float]]`: keep strikes with OI >= 10, ask > 0, ask - bid <= 0.25; point = (strike / divisor, (bid + ask) / 2); ascending; then a running minimum so P(above) never rises with the strike. KXISMPMI's `greater_or_equal` markets are read as "above" (outcomes step 0.1, so the difference is immaterial).
  - `implied_median(points: list[tuple[float, float]], discrete: bool) -> Optional[float]`: None with < 2 points, first p <= 0.5, or last p > 0.5; else the first adjacent pair with p0 > 0.5 >= p1 gives `s1` when discrete, `s0 + (s1 - s0) * (p0 - 0.5) / (p0 - p1)` when continuous.
  - `market_call(title: str, ladder: KalshiLadder, forecast_text: Optional[str]) -> tuple[Optional[MarketCall], Optional[str]]` (call or reason): no forecast -> `NO_FORECAST`; forecast outside `[min - span/2, max + span/2]` of the liquid strikes -> reason containing `"units"`; no median -> `"no 50% crossing among liquid strikes"`; else side = `stats_rules.side(median, forecast, tolerance(forecast_text))`.
